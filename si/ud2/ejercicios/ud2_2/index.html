    UD2.2 · Crear usuarios y grupos desde un TXT¶

    Módulo: Sistemas Informáticos · 1.º DAM
    Duración orientativa: 60 minutos
    Modalidad: Individual · Debian GNU/Linux
    Herramientas: Bash, groupadd, useradd, chpasswd, id, groups, chmod y chown

    En esta actividad desarrollarás un script Bash que lea un fichero de texto y cree usuarios de Linux automáticamente. Después comprobarás que los usuarios se han creado, que pertenecen a sus grupos y que los permisos limitan el acceso a una carpeta.

    Entorno de prácticas

    Crear usuarios modifica el sistema y requiere privilegios de administrador. Realiza la práctica en un entorno Debian de pruebas donde tengas autorización para administrar cuentas. Si no dispones de estos permisos, consulta al profesor.

    1. Fichero de usuarios¶

    El script principal estará en:

    /workspace/ud2/ud2_2.sh

    Para no subir contraseñas a Git, guarda el fichero de entrada fuera del repositorio:

    /tmp/ud2_usuarios.txt

    Cada línea tendrá exactamente cuatro campos separados por punto y coma:

    usuario;grupo;contraseña;shell

    Introduce estas tres cuentas de pruebas, sin incluir la línea de cabecera:

    ud2ana;ud2aula;CAMBIAR_CLAVE_1;/bin/bash
ud2luis;ud2aula;CAMBIAR_CLAVE_2;/bin/bash
ud2invitado;ud2visitas;CAMBIAR_CLAVE_3;/usr/sbin/nologin

    Sustituye CAMBIAR_CLAVE_1, CAMBIAR_CLAVE_2 y CAMBIAR_CLAVE_3 por tres contraseñas temporales distintas, inventadas para esta práctica y que no utilices en ningún otro servicio.

    Campo Significado
    usuario Nombre de la cuenta que se va a crear
    grupo Grupo principal del usuario
    contraseña Contraseña inicial de la cuenta
    shell Programa que se ejecuta al iniciar una sesión; nologin impide el acceso interactivo normal

    Contraseñas

    El TXT contiene contraseñas en texto claro: úsalo solo como fichero temporal del laboratorio, no lo subas a Gitea o GitHub y elimínalo al terminar. No incluyas las contraseñas en capturas, mensajes ni respuestas. En entornos reales se deben utilizar mecanismos de aprovisionamiento más seguros.

    2. Script Bash¶

    Crea /workspace/ud2/ud2_2.sh. Debe realizar las siguientes operaciones por cada línea, y en este orden:

    1. Leer los cuatro datos: usuario, grupo, password y shell.
    2. Comprobar si el grupo ya existe. Si no existe, crearlo con groupadd.
    3. Comprobar si el usuario ya existe. Si no existe, crearlo con useradd y las opciones necesarias para:
      • crear su carpeta personal en /home;
      • asignar el grupo principal;
      • establecer la shell indicada en el TXT.
    4. Establecer la contraseña inicial mediante chpasswd, solo para los usuarios nuevos.
    5. Mostrar por pantalla un mensaje que indique qué usuario se ha creado y a qué grupo pertenece; si ya existía, mostrarlo y continuar con el siguiente.

    Pistas¶

    Para separar los campos de una línea:

    IFS=';' read -r usuario grupo password shell <<< "$linea"

    Puedes utilizar un bucle while read para leer el fichero completo. Recuerda que:

    • grep puede ayudarte a comprobar si un grupo aparece en /etc/group (comparando el nombre completo del grupo).
    • id -u "$usuario" permite comprobar si existe una cuenta de usuario.
    • groupadd crea un grupo nuevo.
    • useradd -m -g ... -s ... permite crear un usuario con carpeta personal, grupo y shell.
    • chpasswd recibe una línea con el formato usuario:contraseña por su entrada estándar. No muestres ni pases la contraseña como argumento de un comando.

    No complicar el programa

    En esta primera actividad no es necesario crear un menú ni validar todos los posibles errores del TXT. Trabajaremos con las tres líneas proporcionadas. Eso sí: el script no debe intentar crear otra vez cuentas que ya existan ni cambiar sus contraseñas por volverlo a ejecutar.

    Cuando termines, concede permiso de ejecución al script y ejecútalo solo en el entorno de pruebas, con privilegios de administrador:

    chmod u+x /workspace/ud2/ud2_2.sh
sudo /workspace/ud2/ud2_2.sh

    3. Pruebas de usuarios¶

    Utiliza los siguientes comandos para comprobar las cuentas creadas:

    id ud2ana
id ud2luis
id ud2invitado

groups ud2ana
groups ud2invitado

sudo -u ud2ana ls -la /home/ud2ana
sudo -u ud2luis ls -la /home/ud2luis

    En la salida de ls -la, la entrada . indica los permisos del propio directorio y .. representa su directorio superior.

    Responde en /workspace/ud2/respuestas_ud2_2.md:

    1. ¿A qué grupo principal pertenecen ud2ana y ud2luis?
    2. ¿A qué grupo principal pertenece ud2invitado?
    3. ¿Qué propietario tiene /home/ud2ana? ¿Se ha creado su directorio personal?

    Comprobar una sesión¶

    Desde una sesión de usuario normal, prueba:

    su - ud2ana
whoami
pwd
exit

    Introduce su contraseña de prueba cuando se solicite. A continuación, intenta iniciar una sesión interactiva como ud2invitado con su - ud2invitado.

    Pregunta: ¿Por qué ud2invitado no obtiene una shell interactiva normal? Comprueba qué shell tiene asignada cada cuenta.

    Atención

    Si ejecutas su siendo root, puede que no te solicite la contraseña. Para probar la autenticación, hazlo desde una cuenta sin privilegios. El comportamiento concreto también puede depender de la configuración del contenedor.

    4. Pruebas de permisos por grupo¶

    Ahora crea una carpeta compartida para los usuarios del grupo ud2aula:

    sudo mkdir /tmp/ud2_compartida
sudo chown root:ud2aula /tmp/ud2_compartida
sudo chmod 770 /tmp/ud2_compartida
sudo ls -la /tmp/ud2_compartida

    Si la carpeta ya existe

    No reutilices una carpeta de otra persona: realiza la prueba en una instancia limpia del laboratorio o utiliza otra ruta de pruebas exclusiva. No borres directorios que no hayas creado.

    Ejecuta ahora estas pruebas, una a una:

    sudo -u ud2ana touch /tmp/ud2_compartida/ana.txt
sudo -u ud2luis touch /tmp/ud2_compartida/luis.txt
sudo -u ud2invitado touch /tmp/ud2_compartida/invitado.txt
sudo -u ud2ana ls -la /tmp/ud2_compartida

    Los dos primeros usuarios deberían poder crear sus archivos. El tercero debería recibir «Permiso denegado» porque no pertenece al grupo propietario y el directorio no concede permisos a otros.

    ¿Qué prueba sudo -u?

    Ejecuta el comando indicado con la identidad de otro usuario. Permite comprobar sus permisos sobre un directorio, pero no comprueba su contraseña ni implica un inicio de sesión interactivo.

    Responde:

    1. ¿Por qué ud2ana y ud2luis pueden escribir dentro de la carpeta?
    2. ¿Por qué ud2invitado no puede crear su archivo?
    3. ¿Qué significa 770 en este caso?
    4. ¿Qué cambiaría si estableciésemos chmod 700 /tmp/ud2_compartida?

    5. Comprobación final¶

    • El TXT tiene tres líneas con cuatro campos separados por ;.
    • El script crea primero los grupos necesarios y después los usuarios.
    • Los usuarios tienen su directorio personal y la shell correspondiente.
    • Al ejecutar el script por segunda vez, no se vuelven a crear usuarios ni se cambian sus contraseñas.
    • Has probado id, groups y ls -la.
    • Has comprobado el acceso a la carpeta compartida con los tres usuarios.
    • Has respondido las preguntas sin incluir contraseñas.

    Entrega¶

    Entrega únicamente estos dos archivos de tu repositorio de trabajo:

    /workspace/ud2/ud2_2.sh
/workspace/ud2/respuestas_ud2_2.md

    Puedes subirlos individualmente con:

    cd /workspace
git status
git add ud2/ud2_2.sh ud2/respuestas_ud2_2.md
git commit -m "Completar ejercicio UD2.2"
git pull
git push

    No subas /tmp/ud2_usuarios.txt ni ningún archivo que contenga contraseñas. Cuando hayas terminado las comprobaciones, elimina el TXT temporal. Conserva las cuentas de prueba hasta que el profesor haya revisado el ejercicio; después, se pueden eliminar solo en el entorno de laboratorio.
