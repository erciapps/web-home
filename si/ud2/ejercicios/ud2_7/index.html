    UD2.7 · Preparación de Debian y servicios con systemd¶

    2. Preparar .gitignore en el repositorio actual¶

    Antes de utilizar el nuevo Debian, entra en el repositorio Git en el que trabajas actualmente. Crea o edita el archivo .gitignore de la raíz del repositorio (por ejemplo, /workspace/.gitignore) e incorpora lo siguiente:

    # Entornos virtuales
.venv/
venv/
env/

# Variables de entorno y credenciales
.env
.env.*
!.env.example
!.env.template

# Python
__pycache__/
*.py[cod]
*.egg-info/
.pytest_cache/
.mypy_cache/

# Editores y temporales
.idea/
.vscode/
*.log
*.tmp
*.bak
*~

# Bases de datos locales
*.sqlite
*.sqlite3
*.db

# Aplicaciones web
node_modules/
dist/
build/

# Sistema operativo
.DS_Store
Thumbs.db

    Este archivo evita incluir entornos virtuales, variables de entorno y archivos temporales. Desde la raíz de tu repositorio actual, comprueba los cambios, confirma el archivo y súbelo al servidor Git:

    git status
git add .gitignore
git commit -m "Añadir .gitignore"
git push

    Una vez subido, ya puedes preparar el Debian nuevo y clonar el repositorio con el .gitignore incluido.

    3. Preparar Git en el nuevo Debian¶

    Ahora sí, entra en tu nuevo Debian. Instala Git y las herramientas de Python. Estos comandos requieren permisos de administrador.

    apt update
apt install -y git python3 python3-venv python3-pip
git --version

    Configura la identidad con la que harás los commits:

    git config --global user.name "Nombre Apellidos"
git config --global user.email "tu-correo@ejemplo.com"
git config --global --list

    Para que Git recuerde tus credenciales HTTPS entre operaciones:

    git config --global credential.helper store

    Al hacer el primer git clone, git pull o git push, introduce tu usuario y el token de acceso del servidor Git cuando te pida la contraseña. Git guardará la credencial en ~/.git-credentials. Comprueba sus permisos:

    [ ! -f ~/.git-credentials ] || chmod 600 ~/.git-credentials

    Este método guarda el token sin cifrar. Úsalo solo en tu Debian individual y no subas nunca ese archivo al repositorio. La configuración se guarda para el usuario Linux que ejecuta los comandos.

    Clona en /workspace el repositorio que acabas de actualizar. La carpeta debe estar vacía:

    mkdir -p /workspace
cd /workspace
git clone URL_DEL_REPOSITORIO .

    Si ya tienes el repositorio clonado, entra en /workspace y utiliza git pull en lugar de clonarlo de nuevo.

    4. Crear un entorno virtual de Python¶

    Prepara la carpeta de la actividad:

    mkdir -p /workspace/ud2/servicios
cd /workspace/ud2/servicios
python3 -m venv .venv
source .venv/bin/activate
pip install flask
pip freeze > requirements.txt

    El entorno virtual contiene las bibliotecas de este proyecto y no se debe subir a Git.

    Para salir del entorno:

    deactivate

    Para volver a activarlo:

    cd /workspace/ud2/servicios
source .venv/bin/activate

    5. Actividad: ejecutar una aplicación Python como servicio¶

    Un servicio de sistema se define mediante un archivo .service y se administra con systemctl. El objetivo es que tu aplicación continúe funcionando sin mantener una terminal abierta y se inicie al arrancar Debian.

    5.1. Crear la aplicación¶

    Crea /workspace/ud2/servicios/app.py:

    from flask import Flask

app = Flask(__name__)

@app.route("/")
def inicio():
    return "Servicio de Sistemas Informáticos"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=11000, debug=False)

    Sustituye el puerto 11000 por el primero de tu rango asignado. Modifica el mensaje para incluir el nombre de tu máquina y añade una segunda ruta /estado que devuelva Servicio activo.

    Prueba la aplicación:

    cd /workspace/ud2/servicios
source .venv/bin/activate
python app.py

    Comprueba que responde y deténla con Ctrl+C antes de configurar el servicio.

    5.2. Crear la unidad de systemd¶

    Comprueba que Debian utiliza systemd:

    ps -p 1 -o comm=
whoami

    Crea /workspace/ud2/servicios/ud2-servicio.service:

    [Unit]
Description=Aplicacion Flask de Sistemas Informaticos
After=network.target

[Service]
Type=simple
User=TU_USUARIO
WorkingDirectory=/workspace/ud2/servicios
ExecStart=/workspace/ud2/servicios/.venv/bin/python /workspace/ud2/servicios/app.py
Restart=on-failure

[Install]
WantedBy=multi-user.target

    Sustituye TU_USUARIO por el usuario Linux que ejecutará la aplicación, obtenido con whoami. Ese usuario debe tener acceso a /workspace/ud2/servicios. No hace falta activar el entorno virtual en el archivo: ExecStart utiliza directamente su intérprete de Python.

    5.3. Explicación del archivo .service¶

    Un archivo .service se divide en tres secciones principales:

    Apartado Función
    [Unit] Información general del servicio y orden de inicio.
    Description= Nombre o descripción que muestra systemctl.
    After=network.target Ordena el inicio después del objetivo de red; no garantiza que ya exista conexión a Internet.
    [Service] Indica cómo se ejecuta el programa.
    Type=simple Considera iniciado el servicio al arrancar el proceso principal.
    User=TU_USUARIO Usuario de Linux que ejecutará el programa.
    WorkingDirectory= Directorio de trabajo desde el que se ejecutará el programa.
    ExecStart= Comando completo que inicia el programa.
    Restart=on-failure Reinicia el programa si falla, pero no cuando se detiene con systemctl stop.
    [Install] Establece cómo se habilita el arranque automático del servicio.
    WantedBy=multi-user.target Permite habilitarlo para el arranque normal del sistema con systemctl enable.

    En el servicio de Python, ExecStart utiliza /workspace/ud2/servicios/.venv/bin/python, el intérprete del entorno virtual, para ejecutar app.py. Por eso no hace falta utilizar source .venv/bin/activate en el archivo de servicio.

    5.4. Instalar e iniciar el servicio¶

    Instala y arranca el servicio con permisos de administrador:

    cp /workspace/ud2/servicios/ud2-servicio.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now ud2-servicio.service
systemctl status ud2-servicio.service

    5.5. Comprobar su funcionamiento¶

    Utiliza los siguientes comandos:

    systemctl stop ud2-servicio.service
systemctl start ud2-servicio.service
systemctl restart ud2-servicio.service
systemctl status ud2-servicio.service
journalctl -u ud2-servicio.service -n 20 --no-pager

    Comprueba desde un navegador de la red del instituto:

    http://192.168.29.133:TU_PUERTO
http://192.168.29.133:TU_PUERTO/estado

    Sustituye TU_PUERTO por el puerto de tu aplicación. Comprueba también que el servicio vuelve a iniciarse al reiniciar tu Debian.

    6. Actividad: ejecutar un script Bash como servicio¶

    Ahora crearás otro servicio, esta vez sin Python. El script escribirá la fecha en el registro del servicio cada diez segundos y seguirá funcionando aunque cierres la terminal.

    6.1. Crear el script¶

    Crea /workspace/ud2/servicios/registro.sh:

    #!/bin/bash

while true; do
    echo "Servicio Bash activo: $(date)"
    sleep 10
done

    Asígnale permisos de ejecución:

    chmod +x /workspace/ud2/servicios/registro.sh

    Prueba el script y detenlo con Ctrl+C:

    /workspace/ud2/servicios/registro.sh

    6.2. Crear el servicio de Bash¶

    Crea /workspace/ud2/servicios/ud2-bash.service:

    [Unit]
Description=Servicio Bash de Sistemas Informaticos
After=network.target

[Service]
Type=simple
User=TU_USUARIO
WorkingDirectory=/workspace/ud2/servicios
ExecStart=/bin/bash /workspace/ud2/servicios/registro.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target

    Sustituye TU_USUARIO por tu usuario de Linux. Debe poder leer el script y acceder a la carpeta.

    Este archivo tiene las mismas secciones que el servicio Python. La diferencia principal está en ExecStart:

    • Python: inicia app.py con el intérprete de .venv.
    • Bash: inicia registro.sh con /bin/bash.

    El proceso de Bash permanece en ejecución gracias al bucle while. Los mensajes de echo se guardan en el registro del servicio y pueden consultarse con journalctl.

    6.3. Activar y comprobar el servicio Bash¶

    Instala el archivo y arranca el servicio con permisos de administrador:

    cp /workspace/ud2/servicios/ud2-bash.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now ud2-bash.service
systemctl status ud2-bash.service

    Consulta sus mensajes:

    journalctl -u ud2-bash.service -n 20 --no-pager

    Comprueba que aparecen líneas nuevas con la fecha. Después prueba:

    systemctl stop ud2-bash.service
systemctl start ud2-bash.service
systemctl restart ud2-bash.service
systemctl status ud2-bash.service

    6.4. Comandos de administración de servicios¶

    Comando Función
    systemctl daemon-reload Recarga los archivos de servicio después de crearlos o modificarlos.
    systemctl start nombre.service Inicia el servicio en este momento.
    systemctl stop nombre.service Detiene el servicio.
    systemctl restart nombre.service Detiene y vuelve a iniciar el servicio.
    systemctl status nombre.service Muestra su estado.
    systemctl enable nombre.service Habilita el inicio automático; no arranca inmediatamente el servicio.
    systemctl disable nombre.service Deshabilita el inicio automático; no detiene el servicio actual.
    systemctl enable --now nombre.service Habilita el inicio automático y lo arranca ahora.
    journalctl -u nombre.service Muestra los mensajes registrados por el servicio.

    Tras habilitarlos, comprueba que los dos servicios vuelven a arrancar al reiniciar el Debian.

    7. Entrega¶

    Sube al repositorio:

    • /workspace/.gitignore
    • /workspace/ud2/servicios/app.py
    • /workspace/ud2/servicios/requirements.txt
    • /workspace/ud2/servicios/ud2-servicio.service
    • /workspace/ud2/servicios/registro.sh
    • /workspace/ud2/servicios/ud2-bash.service
    • /workspace/ud2/servicios/respuestas.md

    En respuestas.md, indica:

    1. Tu puerto TCP y la URL desde la que accedes a Flask.
    2. Qué aparece al consultar el estado del servicio Python y del servicio Bash.
    3. Para qué sirven [Unit], [Service] y [Install].
    4. Qué hacen User, WorkingDirectory, ExecStart y Restart.
    5. La diferencia entre start y enable.
    cd /workspace
git status
git add .gitignore ud2/servicios/
git commit -m "UD2.7 Servicios Python y Bash con systemd"
git push

    No subas .venv, .env ni credenciales. Los servicios se utilizarán únicamente para las prácticas de la red del instituto.
