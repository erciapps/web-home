    UD3.2 · Configuración de un router MikroTik, DHCP y acceso a Internet¶

    Módulo: Sistemas Informáticos · 1.º DAM
    Modalidad: Individual · GNS3
    Herramientas: GNS3, MikroTik CHR, WinBox, Webterm, VPCS, switch, NAT, ping, show arp e ip neigh
    Resultado de aprendizaje: RA5 · Criterios: a), b), d), e) y g)

    Objetivo¶

    Ampliar la red local de la UD3.1 añadiendo un router MikroTik, configurar el servicio DHCP, administrarlo mediante WinBox y utilizar Webterm para las comprobaciones. Comparar las tablas ARP de los ordenadores y del router. Comprobar también la conexión entre la LAN e Internet.

    1. Crear el proyecto¶

    Crea un proyecto en GNS3 denominado UD3_2_ROUTER_damXX, sustituyendo damXX por tu usuario. Puedes partir de la topología de la UD3.1.

    Tu proyecto debe contener:

    • Un router MikroTik CHR.
    • Un nodo MikroTikWinBox2026.
    • Un switch Ethernet.
    • Tres ordenadores VPCS.
    • Un equipo Webterm, con navegador y terminal Linux.
    • Un nodo NAT de GNS3.

    Realiza las conexiones de esta forma:

                 NAT (GNS3)
                 |
             ether1 (WAN)
               MikroTik
             ether2 (LAN)
                 |
               Switch
          /    /   \     \      \
        PC1   PC2   PC3  Webterm  WinBox

    Conexiones del router

    Conecta el puerto LAN ether2 de MikroTik al switch. El puerto WAN ether1 va al nodo NAT. No intercambies los puertos.

    Mantén los nombres de los dispositivos identificados con tu usuario.

    2. Configurar WinBox y Webterm en GNS3¶

    Los dos nodos Docker, MikroTikWinBox2026 y Webterm, deben configurarse para obtener su IPv4 mediante DHCP. No basta con conectarlos al switch.

    1. Detén el nodo y abre sus propiedades (Configure).
    2. En Network, selecciona eth0 y mantenla habilitada.
    3. En IPv4 configuration → Addressing mode, selecciona DHCP.
    4. Deja DNS nameservers vacío para recibir el DNS por DHCP.
    5. Deja IPv6 en Disabled para esta práctica.
    6. Pulsa Apply network configuration y después Apply.
    7. Repite los pasos en ambos nodos y arráncalos.

    Configuración inicial

    Antes de activar el DHCP del router, los nodos pueden no tener IPv4. WinBox permite intentar el acceso por MAC desde la misma LAN. Si no funciona, utiliza la consola de MikroTik para asignar provisionalmente la IP LAN a ether2 y configura temporalmente una IP del mismo segmento en WinBox; tras activar DHCP vuelve a seleccionar DHCP.

    Acceder al router con WinBox¶

    Conecta el nodo MikroTikWinBox2026 al switch y arráncalo junto al router. En WinBox, abre Neighbors, selecciona la dirección MAC del router y conecta con el usuario de administración. No necesitas una IP inicial en la LAN.

    3. Configurar WAN, LAN, DHCP y DNS¶

    Cada alumno utilizará la red 10.XX.1.0/24, donde XX es el número de su usuario. Para damx utiliza XX=120.

    En Quick Set, configura:

    Parámetro Valor
    Mode Router
    Address Acquisition Static
    WAN IP IP de tu usuario según la tabla de la UD3
    WAN Netmask /24
    Gateway 192.168.122.1
    DNS Servers 192.168.122.1
    LAN IP 10.XX.1.1
    LAN Netmask /24
    Bridge All LAN Ports Desmarcado
    DHCP Server Marcado
    DHCP Server Range 10.XX.1.100-10.XX.1.149
    NAT Marcado
    VPN Access Desmarcado

    Aplica los cambios. En IP → Addresses, comprueba que ether1 corresponde a la WAN y ether2 a la LAN. En IP → DNS, configura 192.168.122.1 y deja Allow Remote Requests desmarcado. En IP → DHCP Server → Networks, abre tu red y establece DNS Servers = 192.168.122.1.

    Una vez activado el DHCP, reinicia WinBox y Webterm si no han obtenido dirección. Puedes conectarte al router por su IP LAN 10.XX.1.1 desde WinBox. Comprueba desde la terminal de Webterm:

    ip addr
ip route
cat /etc/resolv.conf

    El DNS recibido debe ser 192.168.122.1. Comprueba en IP → DHCP Server → Leases que WinBox y Webterm han obtenido una dirección.

    4. Configurar PC1, PC2 y PC3 mediante DHCP¶

    Los ordenadores ya no utilizarán las direcciones IP fijas de la UD3.1: deben obtener su configuración de forma automática desde MikroTik.

    Desde la consola de cada VPCS:

    ip dhcp
show ip

    Comprueba que cada equipo recibe una dirección IP de tu rango, una máscara /24 y como puerta de enlace la IP LAN de MikroTik.

    Si lo prefieres, puedes dejar configurado el comando dhcp desde las propiedades del propio nodo VPCS para que solicite la dirección al arrancar. Comprueba igualmente el resultado desde la consola.

    Realiza ping desde PC1 hacia PC2, PC3 y la IP LAN del router.

    5. Comprobar la WAN y el acceso a Internet¶

    La WAN de MikroTik debe conservar la IP estática asignada a tu usuario.

    En WinBox, consulta IP → Addresses e IP → Routes para comprobar la IP WAN y la puerta de enlace. Comprueba que el nodo NAT está conectado correctamente.

    Desde Webterm realiza:

    ping -c 4 10.XX.1.1
ping -c 4 1.1.1.1
ping -c 4 google.es

    Sustituye XX por tu identificador. Desde los VPCS, comprueba también si puedes alcanzar una dirección externa:

    ping 1.1.1.1

    Si la LAN funciona pero no hay conexión exterior, revisa las conexiones, el estado de la WAN y la salida NAT de MikroTik, sin cambiar la dirección WAN asignada.

    6. Comparar las tablas ARP¶

    6.1. En PC1 (VPCS)¶

    Ejecuta:

    show arp
ping 10.XX.1.1
show arp

    Después realiza ping a la dirección actual de PC2 y vuelve a ejecutar show arp.

    Observa qué direcciones IP y MAC aparecen.

    6.2. En Webterm (Linux)¶

    Desde la terminal:

    ip neigh show

    Haz ping a la IP real de PC1 (consulta primero su show ip), por ejemplo:

    ping -c 4 10.XX.1.100
ip neigh show

    La dirección .100 es solamente un ejemplo: DHCP puede haber asignado otra distinta.

    6.3. En MikroTik¶

    En WinBox, abre IP → ARP y observa las direcciones IP y MAC de los vecinos.

    Recuerda

    La tabla ARP relaciona direcciones IP y MAC de vecinos conocidos. La tabla MAC del switch relaciona las MAC aprendidas con sus puertos. Si PC1 hace ping a PC2 dentro de la misma LAN, no necesita que los paquetes pasen por MikroTik.

    7. Preguntas en el README del proyecto¶

    En GNS3 abre Edit project → Readme.

    Escribe allí tu nombre y primer apellido, usuario, red utilizada y respuestas breves a estas preguntas:

    1. ¿Para qué sirve el router MikroTik si los ordenadores ya podían comunicarse mediante el switch?
    2. ¿Qué diferencia existe entre la dirección LAN y la dirección WAN del router?
    3. ¿Qué configuración reciben los equipos automáticamente mediante DHCP?
    4. ¿Qué función tiene la puerta de enlace al acceder a Internet?
    5. ¿Qué diferencias observas entre las tablas ARP de VPCS, Webterm y MikroTik?
    6. Si PC1 se comunica con PC2, ¿deben pasar los paquetes por el router? Razona la respuesta.

    El README utiliza Markdown. Comprueba que los cambios están guardados antes de exportar el proyecto.

    8. Entrega¶

    Comprueba que:

    • Los tres VPCS, Webterm y WinBox están conectados al switch; los dos nodos Docker están configurados por DHCP.
    • MikroTik tiene su LAN en 10.XX.1.1/24 y conserva la IP de su WAN.
    • El servidor DHCP asigna direcciones del rango indicado.
    • Puedes administrar MikroTik desde el nodo WinBox y Webterm recibe el DNS correcto.
    • Los equipos pueden comunicarse entre sí y salir a Internet.
    • Has consultado las tablas ARP de los tres entornos.
    • El README del proyecto incluye todas las respuestas.

    Detén los dispositivos y utiliza Export portable project para entregar:

    UD3_2_ROUTER_damXX.gns3project

    No se requiere PDF ni capturas. El proyecto debe poder importarse y comprobarse.

    Criterios de evaluación relacionados¶

    Criterio Evidencia de la práctica
    RA5.a — Se ha configurado el protocolo TCP/IP. Direcciones, máscara, puerta de enlace y DHCP.
    RA5.b — Se han configurado redes de área local cableadas. LAN funcional con cuatro equipos.
    RA5.d — Se han utilizado dispositivos de interconexión de redes. Router y switch conectados correctamente.
    RA5.e — Se ha configurado el acceso a redes de área extensa. Comprobación de WAN, NAT y acceso exterior.
    RA5.g — Se ha verificado el funcionamiento de la red mediante comandos y herramientas básicas. ping, show ip, show arp e ip neigh.
