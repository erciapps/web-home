## 1. ¿Qué es un proceso?

Un **programa** es el código almacenado en un archivo. Un **proceso** es una instancia de ese programa que se está ejecutando.

Cada proceso tiene un identificador llamado **PID**. El sistema operativo gestiona su ejecución y los recursos que consume.

Prueba estos comandos:

~~~bash
whoami
ps
ps -u "$USER"
ps -ef
top
~~~

En `top` puedes pulsar `q` para salir. Ejecuta también `htop` si está instalado (sal con `q` o F10); si no está instalado, deja constancia en las respuestas. No necesitas instalarlo sin autorización.

2. ¿En qué se diferencia un programa de un proceso?
3. ¿Qué información muestra `top` que no aparece en la salida básica de `ps`?
4. ¿Qué diferencias observas entre `top` y `htop`?

## 2. Ejecutar un proceso en segundo plano

Inicia un proceso sencillo:

~~~bash
sleep 120 &
pid=$!
echo "PID del proceso: $pid"
ps -p "$pid"
~~~

- `sleep 120` espera 120 segundos.
- `&` ejecuta el comando en segundo plano.
- `$!` contiene el PID del último proceso lanzado en segundo plano desde esta shell.

Si continúa activo, finalízalo:

~~~bash
kill "$pid"
ps -p "$pid"
~~~

!!! warning "No mates todos los procesos Python"
    En esta práctica utiliza **solo el PID que acabas de lanzar**. No utilices `killall python3`, `pkill -f python` ni `kill -9` como solución general.

Responde: ¿qué diferencia observas entre ejecutar `sleep 120` y `sleep 120 &`?

## 3. Crear nuestro propio proceso con Python

Crea `/workspace/ud2/ud2_3.py` con el siguiente contenido:

~~~python
import os
import time

print("Mi PID es:", os.getpid(), flush=True)

while True:
    print("El proceso sigue activo", flush=True)
    time.sleep(5)
~~~

Ejecútalo:

~~~bash
python3 /workspace/ud2/ud2_3.py
~~~

En otra terminal, consulta su PID (el número mostrado por Python):

~~~bash
ps -p NUMERO_PID -o pid,ppid,stat,cmd
~~~

Sustituye `NUMERO_PID` por el valor real.

Vuelve a la primera terminal y detén el programa con **Ctrl+C**. Comprueba con `ps` que ya no continúa ejecutándose.

Responde:

1. ¿Qué hace `os.getpid()`?
2. ¿Qué hace `time.sleep(5)`?
3. ¿Para qué sirve `Ctrl+C` cuando el proceso está en primer plano?

## 4. Ejecutar el programa Python en segundo plano

Desde el mismo terminal:

~~~bash
python3 /workspace/ud2/ud2_3.py > /tmp/ud2_3_proceso.log 2>&1 &
pid=$!

echo "$pid"
ps -p "$pid"
cat /tmp/ud2_3_proceso.log
~~~

La redirección `>` escribe la salida en un fichero; `2>&1` une los mensajes de error con la salida estándar.

Detén **ese proceso concreto**:

~~~bash
kill "$pid"
ps -p "$pid"
~~~

!!! tip "Otra herramienta"
    `pgrep -a -u "$USER" python3` permite localizar procesos Python del usuario actual. Úsalo para **consultar**, no para detener todos indiscriminadamente.

## 5. Conocer `pgrep` y `pkill`

`kill` trabaja con un **PID concreto**, mientras que `pkill` busca procesos **por su nombre** y puede afectar a más de uno.

Para probarlo sin afectar a otros procesos, lanza un único `sleep` de prueba:

~~~bash
sleep 120 &
pid=$!
pgrep -a -u "$USER" -x sleep
~~~

Si `pgrep` muestra **solo ese proceso que acabas de lanzar**, puedes finalizarlo por nombre:

~~~bash
pkill -u "$USER" -x sleep
ps -p "$pid"
~~~

!!! warning "Si aparecen varios procesos sleep"
    No utilices `pkill`: podría detener procesos de otras prácticas del mismo usuario. Detén **solo el tuyo** con `kill "$pid"`. No uses `pkill -f python` ni detengas procesos de otros alumnos o del sistema.

Responde en tu informe:

1. ¿Qué diferencia hay entre `kill` y `pkill`?
2. ¿Para qué sirve `pgrep` antes de utilizar `pkill`?
3. ¿Qué hacen `-u "$USER"` y `-x` en estos comandos?
