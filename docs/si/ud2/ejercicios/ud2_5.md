# UD2.5 · Gestor de procesos Linux con Flask y Bash

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Modalidad:** Individual · Debian GNU/Linux  
**Herramientas:** Bash, `ps`, `pgrep`, `pkill`, `kill`, HTML, CSS, Flask y `subprocess`

## 1. Objetivo

Crear una aplicación web que permita **iniciar, consultar el estado y detener cuatro procesos de prueba** mediante scripts Bash y Flask. Reutilizarás los comandos y los formularios trabajados en las prácticas anteriores.

!!! info "Entorno de trabajo"
    Trabaja en tu Debian, dentro de `/workspace/ud2/flask-procesos/`. Ejecuta Flask como usuario normal y utiliza únicamente procesos creados para esta práctica. No detengas SSH, VS Code, Flask ni otros procesos del sistema.

## 2. Crear los procesos de prueba

Crea cuatro scripts dentro de la carpeta `scripts/`:

| Archivo | Tarea simulada |
| --- | --- |
| `backup.sh` | Copia de seguridad |
| `monitor.sh` | Monitorización |
| `servidor.sh` | Servidor |
| `descarga.sh` | Descarga |

**Ejemplo: `scripts/backup.sh`**

~~~bash
#!/bin/bash

while [[ true ]]; do
    sleep 2
done
~~~

Los cuatro scripts pueden tener el mismo contenido: no realizan tareas reales, solo permanecen en ejecución. **No hace falta cambiarles el nombre al proceso.**

Dales permisos de ejecución y prueba a iniciar `backup.sh` desde la raíz del proyecto:

~~~bash
chmod +x scripts/*.sh
./scripts/backup.sh &
~~~

Comprueba qué proceso se ha iniciado:

~~~bash
pgrep -af '/backup[.]sh'
ps -p PID -o pid,stat,args
~~~

Sustituye `PID` por el número real. Como el script se ejecuta con Bash, para localizarlo por su ruta o argumentos es útil `pgrep -f`. Al terminar la prueba, utiliza `kill PID` sobre **tu proceso**.

## 3. Crear los scripts de administración

Crea scripts para estas tres acciones:

| Acción | Qué debe hacer |
| --- | --- |
| **Iniciar** | Comprobar si ya está funcionando. Si no existe, iniciarlo en segundo plano y mostrar su PID. Si ya existe, informar sin duplicarlo. |
| **Estado** | Indicar si funciona y, cuando esté activo, mostrar PID y estado mediante `ps`. |
| **Detener** | Comprobar que existe y solicitar su finalización. Si no existe, mostrar un mensaje. |

Comienza con estos archivos:

- `scripts/iniciar_backup.sh`
- `scripts/check_backups.sh` (consulta del estado del backup)
- `scripts/detener_backup.sh`

Cuando funcionen, realiza lo mismo para `monitor`, `servidor` y `descarga`. Para las consultas de estado puedes utilizar nombres como `check_monitor.sh`, `check_servidor.sh` y `check_descarga.sh`.

!!! tip "Pistas de Bash"
    Utiliza `pgrep`, `ps`, `kill` o `pkill`, condiciones `if` y mensajes `echo`. Recuerda que `&` ejecuta en segundo plano y `$!` permite obtener el PID recién lanzado. Al arrancar los procesos desde un script de control, redirige su entrada y salida para que el script de control termine sin quedarse esperando.

!!! warning "Identifica bien los procesos"
    Evita búsquedas demasiado amplias: por ejemplo, `pgrep -f backup` podría coincidir también con `iniciar_backup.sh`. Comprueba las coincidencias antes de detener ningún proceso. No utilices `sudo`.

## 5. Interfaz web

Crea `templates/index.html` con:

- Un título y una descripción.
- Un formulario con **un desplegable** para elegir `backup`, `monitor`, `servidor` o `descarga`.
- Tres botones de envío: **Iniciar**, **Estado** y **Detener**.
- Una zona donde mostrar los mensajes devueltos por Flask.

El formulario enviará una petición **POST** a `/proceso` con estos dos campos:

| Campo | Valores |
| --- | --- |
| `proceso` | `backup`, `monitor`, `servidor`, `descarga` |
| `accion` | `iniciar`, `estado`, `detener` |

**Elementos HTML que necesitarás:** `form`, `select`, `option`, `button`, `div` y `pre`. Utiliza `name` y `value` para enviar la información. No se proporciona el HTML resuelto: debes construirlo.

## 6. Aplicación Flask

Implementa dos endpoints:

| Ruta | Método | Función |
| --- | --- | --- |
| `/` | GET | Mostrar el formulario |
| `/proceso` | POST | Recibir el proceso y la acción, realizar la operación y mostrar el resultado |

### Conceptos para el endpoint `/proceso`

**Obtener la carpeta en la que está `app.py`:**

~~~python
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent
~~~

`BASE_DIR` es la ruta absoluta del directorio de la aplicación. Así podremos ejecutar scripts aunque arranquemos Flask desde otra carpeta.

**Recibir los dos valores del formulario:**

~~~python
nombre = request.form["proceso"]
accion = request.form["accion"]
~~~

**Ejecutar un script de ejemplo y recoger su salida:**

~~~python
resultado = subprocess.run(
    ["bash", "scripts/check_backups.sh"],
    cwd=BASE_DIR,
    capture_output=True,
    text=True
)

mensaje = resultado.stdout
~~~

- `subprocess.run()` ejecuta el script y espera a que termine.
- `cwd=BASE_DIR` establece la carpeta principal del proyecto como directorio de trabajo; desde ahí se encuentra `scripts/check_backups.sh`.
- `capture_output=True` captura la salida y los errores.
- `text=True` devuelve el resultado como texto.
- `resultado.stdout` contiene los mensajes normales del script.

**Mostrar el resultado en la página:**

~~~python
return render_template("index.html", mensaje=mensaje)
~~~

Tu endpoint debe validar los valores del formulario, ejecutar únicamente los scripts autorizados para esta práctica y devolver su respuesta. El ejemplo anterior es solo una consulta de estado, **no la solución completa**.

!!! warning "Seguridad"
    No permitas ejecutar comandos arbitrarios escritos desde el navegador, no uses `shell=True` con datos del formulario y no ejecutes Flask como administrador. Realiza la práctica en el entorno local de laboratorio.

## 7. Comprobaciones y entrega

Comprueba desde la web y desde otra terminal que puedes:

1. Iniciar un proceso y consultar su PID.
2. Intentar iniciarlo de nuevo sin crear otra instancia.
3. Consultar si está activo y su estado.
4. Detenerlo y confirmar que ha finalizado.
5. Repetir las pruebas con los cuatro procesos.

**Entrega:** todos los archivos de `flask-procesos/` (Flask, HTML, CSS y scripts Bash) y un `README.md` breve con las instrucciones para ejecutar la aplicación. No subas entornos virtuales ni archivos temporales.
