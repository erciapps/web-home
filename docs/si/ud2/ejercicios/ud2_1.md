# UD2.1 · Permisos y propietarios en Linux

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Duración orientativa:** 60 minutos  
**Modalidad:** Individual · Debian GNU/Linux  
**Herramientas:** terminal de VS Code, `ls`, `stat`, `chmod`, `chown`

En esta práctica vas a **interpretar y modificar permisos reales** de archivos y directorios. También comprobarás qué cambios introduce `chown` y por qué el permiso `x` no significa lo mismo en un archivo que en una carpeta.

!!! info "Zona de trabajo"
    Trabaja **solo** dentro de `/workspace/ud2/pruebas/ud2_1/`. No utilices `sudo` salvo en el apartado expresamente indicado. No cambies permisos ni propietarios de carpetas generales del sistema.

## 1. Preparación de la estructura

Desde el terminal, crea esta estructura:

```text
/workspace/ud2/
├── pruebas/
│   └── ud2_1/
│       ├── documentos/
│       │   └── informe.txt
│       ├── privado/
│       │   └── clave.txt
│       └── scripts/
│           └── iniciar.sh
└── respuestas_ud2_1.md
```

Puedes utilizar estos comandos **solo para preparar los archivos**:

```bash
mkdir -p /workspace/ud2/pruebas/ud2_1/{documentos,privado,scripts}

echo "Informe de UD2" > /workspace/ud2/pruebas/ud2_1/documentos/informe.txt
echo "Información privada" > /workspace/ud2/pruebas/ud2_1/privado/clave.txt

printf '#!/usr/bin/env bash\necho "Prueba UD2.1"\n' > /workspace/ud2/pruebas/ud2_1/scripts/iniciar.sh

touch /workspace/ud2/respuestas_ud2_1.md
```

!!! warning "Antes de continuar"
    No uses `chmod -R 777` ni `chown -R` sobre `/workspace`. En todos los pasos indica **el archivo o directorio concreto** que vas a modificar.

## 2. Investigar los permisos actuales

Entra en `/workspace/ud2/pruebas/ud2_1/` y utiliza:

```bash
whoami
id
ls -l documentos/informe.txt
ls -ld documentos privado scripts
stat -c '%A %a %U:%G %n' documentos/informe.txt
```

En `respuestas_ud2_1.md` anota:

1. Tu nombre de usuario y tu grupo principal.
2. El usuario propietario y el grupo propietario de `informe.txt`.
3. Los permisos actuales de `informe.txt`, en formato simbólico y numérico.
4. La diferencia entre `ls -l documentos` y `ls -ld documentos`.

## 3. Cambiar permisos con `chmod` numérico

Utiliza `chmod` con **tres cifras** para conseguir lo siguiente. Debes calcular tú los valores:

| Elemento | Permisos que debe tener al terminar |
| --- | --- |
| `documentos/informe.txt` | Propietario: leer y escribir; grupo: leer; otros: ninguno |
| `privado/clave.txt` | Propietario: leer y escribir; grupo y otros: ninguno |
| `privado/` | Propietario: leer, escribir y entrar; grupo y otros: ninguno |
| `scripts/` | Propietario: todos; grupo: leer y entrar; otros: ninguno |
| `scripts/iniciar.sh` | Propietario: leer, escribir y ejecutar; grupo: leer y ejecutar; otros: ninguno |

Comprueba cada resultado con `ls -l`, `ls -ld` o `stat` según corresponda.

Después ejecuta `scripts/iniciar.sh` y comprueba que muestra el mensaje de prueba.

!!! tip "Recuerda"
    En un directorio, **entrar** significa disponer del permiso `x`. En un archivo de script, ejecutar requiere `x` sobre el archivo, además de poder atravesar los directorios necesarios.

## 4. Cambiar permisos con `chmod` simbólico

Ahora repite el cambio de permisos de **`scripts/iniciar.sh`**, pero empleando los símbolos `u`, `g`, `o`, `+` y `-`.

1. Deja inicialmente el archivo con permisos `rw-r--r--`.
2. Añade ejecución al propietario.
3. Añade ejecución al grupo.
4. Quita lectura al resto de usuarios.
5. Comprueba que el resultado final es `rwxr-x---`.

Escribe en el informe los **cuatro comandos** utilizados y explica qué hace cada uno.

## 5. ¿Qué sucede al quitar `x` de un directorio?

Trabaja sobre el directorio `privado`, que has creado tú.

1. Comprueba que inicialmente puedes leer `privado/clave.txt`.
2. Quita **solo** el permiso `x` del propietario del directorio `privado`.
3. Intenta leer otra vez el archivo con `cat privado/clave.txt` **sin `sudo`**.
4. Recupera inmediatamente el permiso `x` del propietario y vuelve a comprobar la lectura.

Anota el resultado de ambas pruebas y responde: **¿por qué falla el acceso si el propio `clave.txt` sigue teniendo permiso de lectura para su propietario?**

!!! warning "Si trabajas como root"
    El superusuario puede saltarse controles de acceso ordinarios. Para observar un error «Permiso denegado», esta prueba debe hacerse como usuario normal, sin privilegios especiales.

## 6. Cambiar propietario y grupo con `chown`

Antes de ejecutar cambios, consulta:

```bash
ls -l documentos/informe.txt
id -un
id -gn
```

Si tu entorno permite utilizar `sudo`, practica **únicamente** con el fichero `documentos/informe.txt`:

1. Guarda en tus respuestas su usuario y grupo propietarios originales.
2. Cambia temporalmente su usuario propietario y su grupo a `root:root`, empleando `sudo chown`.
3. Comprueba con `ls -l` y `stat` qué ha cambiado.
4. Restaura inmediatamente el **usuario y grupo originales** con `sudo chown`.
5. Comprueba que al finalizar el archivo ha vuelto a ser tuyo.

!!! info "Si no tienes `sudo`"
    **No es necesario instalarlo ni modificar la configuración del sistema.** En tus respuestas, escribe el comando que utilizarías para cambiar a `root:root`, el de restauración y la explicación de por qué se necesitarían privilegios administrativos. Este paso no debe impedirte terminar la práctica.

**Explica:** si ejecutas `chown` para cambiar el propietario, ¿cambias también automáticamente los bits `rwx` de `chmod`? ¿Por qué puede cambiar quién tiene acceso efectivo al archivo aunque los bits sigan iguales?

## 7. Preguntas de razonamiento

Responde en `respuestas_ud2_1.md`, justificando cada respuesta:

1. Un archivo tiene permisos `-rw-r-----`. ¿Qué puede hacer su propietario, qué puede hacer el grupo y qué pueden hacer otros usuarios?
2. Un directorio tiene permisos `drwxr--r--`. ¿Puede un usuario del grupo listar nombres? ¿Y acceder a `carpeta/archivo.txt` aunque conozca el nombre?
3. Un directorio tiene permisos `drwx--x--x`. ¿Puede otro usuario entrar o acceder a un archivo cuyo nombre ya conoce? ¿Puede obtener un listado normal de sus nombres?
4. Si un archivo no tiene permiso de escritura, ¿puede llegar a borrarse si el directorio que lo contiene permite escribir y atravesarlo? Explica qué se comprueba.
5. ¿En qué se diferencian `chmod 755 directorio` y `chmod 755 programa.sh`?
6. ¿Qué diferencia hay entre `chmod` y `chown`?
