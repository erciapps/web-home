# UD2.8 · Administración de servicios: PostgreSQL, pgAdmin y SSH

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Entorno:** Debian 13  
**Herramientas:** systemd, SSH, PostgreSQL, pgAdmin 4, Apache y ss

## 1. Introducción

En esta unidad continuamos trabajando en el Debian individual preparado en la [UD2.7](ud2_7.md). Instalaremos y configuraremos tres servicios reales:

- **SSH:** acceso remoto y cifrado al servidor.
- **PostgreSQL:** sistema gestor de bases de datos.
- **pgAdmin 4:** interfaz web para administrar PostgreSQL.

**Cada alumno debe cambiar el puerto de escucha de los tres servicios y utilizar exclusivamente los puertos que le corresponden en la tabla de la UD2.7.** Los primeros puertos pueden estar ocupados por aplicaciones anteriores, por lo que comprobaremos que los elegidos estén libres.

Como criterio de organización, utilizaremos el **tercer puerto** del rango para SSH, el **cuarto** para pgAdmin y el **quinto** para PostgreSQL, salvo que ya estén ocupados: en ese caso se escogerán otros tres libres del mismo rango.

En las explicaciones aparecen **2222 (SSH), 8080 (pgAdmin) y 5433 (PostgreSQL)**. Son números ilustrativos, **no los puertos que debéis utilizar**: sustituidlos siempre por los de vuestro Debian.

El acceso a través de la IP del router del instituto, **192.168.29.133**, requiere que exista una redirección del puerto correspondiente hacia la IP privada del Debian (red 192.168.40.0/24).

## 2. Administrar servicios con systemd

En Debian utilizamos el comando **systemctl** para gestionar servicios.

| Comando | Función |
| --- | --- |
| `systemctl status servicio` | Consultar el estado |
| `systemctl start servicio` | Iniciar el servicio |
| `systemctl stop servicio` | Detenerlo |
| `systemctl restart servicio` | Reiniciarlo |
| `systemctl reload servicio` | Recargar su configuración si está admitido |
| `systemctl enable servicio` | Habilitar el arranque automático |
| `systemctl disable servicio` | Deshabilitar el arranque automático |
| `systemctl enable --now servicio` | Habilitar y arrancar |
| `systemctl is-active servicio` | Saber si está activo |
| `systemctl is-enabled servicio` | Saber si está habilitado |
| `systemctl daemon-reload` | Volver a leer los archivos de unidades de systemd |

### ¿Para qué sirve daemon-reload?

Cuando creamos o modificamos una unidad `.service` o `.socket` de systemd, debemos recargar las definiciones:

~~~bash
systemctl daemon-reload
systemctl restart mi-servicio
~~~

**No es lo mismo:**

- **daemon-reload:** systemd vuelve a leer las unidades.
- **restart:** detiene y vuelve a iniciar el servicio.
- **reload:** pide al propio servicio que recargue sus opciones, si lo admite.

Si modificamos `postgresql.conf`, `sshd_config` o `ports.conf`, normalmente no hace falta `daemon-reload`, pues esos archivos no son unidades de systemd.

### Registros del servicio

~~~bash
journalctl -u ssh -n 20 --no-pager
journalctl -u ssh -f
~~~

La primera orden muestra los últimos 20 mensajes; la segunda los sigue en tiempo real.

## 3. Consultar puertos con ss

El comando `ss` permite consultar los sockets de red.

~~~bash
ss -tul
ss -tulnp
~~~

| Opción | Significado |
| --- | --- |
| `-t` | TCP |
| `-u` | UDP |
| `-l` | Solo sockets en escucha |
| `-n` | Mostrar IP y puertos numéricos |
| `-p` | Mostrar los procesos |
| `-a` | Mostrar todos los sockets |

### Columnas de la salida

Por ejemplo, podemos encontrar:

~~~text
Netid  State   Recv-Q  Send-Q  Local Address:Port  Peer Address:Port
tcp    LISTEN  0       128     0.0.0.0:2222       0.0.0.0:*
tcp    LISTEN  0       100     127.0.0.1:smtp     0.0.0.0:*
tcp    LISTEN  0       4096    *:ssh              *:*
~~~

| Columna | Significado |
| --- | --- |
| **Netid** | Protocolo (TCP o UDP) |
| **State** | Estado del socket |
| **Recv-Q** | En TCP LISTEN, conexiones pendientes de aceptar |
| **Send-Q** | En TCP LISTEN, tamaño máximo de esa cola |
| **Local Address:Port** | IP local y puerto donde escucha |
| **Peer Address:Port** | Dirección remota; para un socket en escucha no hay cliente concreto |

En sockets que ya tienen una conexión establecida, `Recv-Q` y `Send-Q` representan cantidades de datos pendientes, no la cola de conexiones.

### Direcciones y estados frecuentes

| Dirección o estado | Significado |
| --- | --- |
| `127.0.0.1:5433` | Solo localhost IPv4 |
| `0.0.0.0:5433` | Todas las interfaces IPv4 del equipo |
| `192.168.40.151:5433` | Solo esa dirección IPv4 |
| `[::1]:5433` | Solo localhost IPv6 |
| `[::]:5433` | Todas las interfaces IPv6 |
| `*:ssh` | Dirección comodín en el puerto del servicio SSH; habitualmente socket IPv6 |
| `LISTEN` | Esperando conexiones TCP |
| `UNCONN` | Habitual en sockets UDP |
| `ESTAB` | Conexión establecida |
| `TIME-WAIT` | Conexión TCP cerrada, mantenida temporalmente |

Un socket IPv6 con dirección comodín puede aceptar también conexiones IPv4 dependiendo de la configuración. `0.0.0.0` no significa todas las direcciones de Internet: significa todas las direcciones **IPv4 locales**.

Podemos consultar por separado IPv4 e IPv6, o las conexiones TCP establecidas:

~~~bash
ss -4 -tln
ss -6 -tln
ss -tn state established
~~~

Para localizar un puerto concreto:

~~~bash
ss -tulnp | grep 2222
~~~

## 4. SSH: acceso remoto al Debian

**SSH** (*Secure Shell*) es el protocolo y también el nombre del programa cliente (`ssh`). El proceso que atiende las conexiones en el servidor se llama **sshd**.

| Elemento | Función |
| --- | --- |
| `ssh` | Cliente que inicia la conexión |
| `sshd` | Servidor que recibe la conexión |
| `openssh-server` | Paquete que instala el servidor |
| `ssh.service` | Unidad del servicio SSH |
| `ssh.socket` | Unidad de systemd que puede gestionar la escucha |

### Instalar y administrar SSH

~~~bash
apt update
apt install -y openssh-server
systemctl status ssh
systemctl enable ssh
~~~

### Crear un usuario para conectarnos

Desde root:

~~~bash
adduser alumno
passwd alumno
id alumno
~~~

`adduser` crea la cuenta Linux; `passwd` permite modificar su contraseña. No necesitamos conectar remotamente como root.

### Configurar sshd y cambiar el puerto

El archivo principal es:

~~~bash
nano /etc/ssh/sshd_config
~~~

Por ejemplo:

~~~ini
Port 2222
PermitRootLogin no
PasswordAuthentication yes
~~~

- **Port:** puerto donde escucha el servidor SSH. Sustituir **2222** por el asignado.
- **PermitRootLogin no:** evita el acceso directo como root.
- **PasswordAuthentication yes:** permite autenticación con contraseña.

También podemos limitar los usuarios autorizados:

~~~ini
AllowUsers alumno
~~~

Si necesitamos otras cuentas, debemos incluirlas también en `AllowUsers`. Algunas opciones pueden estar definidas en `/etc/ssh/sshd_config.d/`.

**Debian 13 puede utilizar ssh.service o ssh.socket.** Antes de cambiar el puerto:

~~~bash
systemctl status ssh
systemctl status ssh.socket
~~~

**Si ssh.socket NO está activo**, verificamos el archivo de configuración y reiniciamos el servicio:

~~~bash
sshd -t
systemctl restart ssh
ss -tulnp | grep 2222
~~~

**Si ssh.socket está activo**, el puerto puede estar definido por systemd. Además de mantener el puerto correcto en `sshd_config`, editamos el socket:

~~~bash
systemctl edit ssh.socket
~~~

En la zona editable añadimos:

~~~ini
[Socket]
ListenStream=
ListenStream=2222
~~~

La primera instrucción vacía la lista anterior de puertos y la segunda establece el nuevo. Después:

~~~bash
sshd -t
systemctl daemon-reload
systemctl restart ssh.socket
~~~

Si `ssh.service` sigue utilizando la escucha anterior, lo reiniciamos de forma controlada:

~~~bash
systemctl restart ssh
~~~

Verificamos el resultado mediante `ss -tulnp`. Todos los valores **2222** deben sustituirse por el puerto SSH del alumno.

**Importante:** al cambiar el puerto, mantenemos una sesión abierta o utilizamos la consola de Proxmox. No cerramos el acceso anterior hasta comprobar que funciona una nueva conexión.

### Conectarnos desde otro equipo

~~~bash
ssh -p 2222 alumno@IP_DEL_DEBIAN
~~~

Desde la red del instituto, si el router tiene preparada la redirección:

~~~bash
ssh -p 2222 alumno@192.168.29.133
~~~

La opción `-p` indica el puerto. El puerto configurado en Debian y el encaminamiento de la red deben permitir esa conexión.

## 5. PostgreSQL: servidor de bases de datos

### Instalación y administración

~~~bash
apt update
apt install -y postgresql postgresql-client

systemctl status postgresql
systemctl start postgresql
systemctl stop postgresql
systemctl restart postgresql
systemctl enable postgresql
~~~

Para consultar la versión, el estado y el puerto del clúster:

~~~bash
pg_lsclusters
~~~

En Debian puede existir una unidad específica del clúster, por ejemplo `postgresql@17-main.service`, además de la unidad general `postgresql.service`.

### Cambiar el puerto de PostgreSQL

Los principales archivos de configuración son:

| Archivo | Función |
| --- | --- |
| `postgresql.conf` | Puerto, interfaces y configuración general |
| `pg_hba.conf` | Reglas de conexión y autenticación |

Su directorio habitual es `/etc/postgresql/VERSION/main/`. Debemos sustituir VERSION por el número indicado en `pg_lsclusters`.

Por ejemplo, si tenemos PostgreSQL 17:

~~~bash
nano /etc/postgresql/17/main/postgresql.conf
~~~

Establecemos:

~~~ini
port = 5433
listen_addresses = '*'
~~~

**5433 es solo un ejemplo.** Cada alumno debe poner el **puerto PostgreSQL asignado en la UD2.7**.

- `port`: puerto en el que escucha PostgreSQL.
- `listen_addresses = 'localhost'`: solo escucha localmente.
- `listen_addresses = '*'`: escucha en todas las interfaces disponibles.

### Configurar las conexiones permitidas

Editamos:

~~~bash
nano /etc/postgresql/17/main/pg_hba.conf
~~~

Como ejemplo de acceso para las redes de laboratorio:

~~~text
host    all    all    192.168.29.0/24    scram-sha-256
host    all    all    192.168.40.0/24    scram-sha-256
~~~

La red de origen debe coincidir con la IP real de los equipos que se conectan. Las conexiones requieren un usuario y contraseña válidos y deben estar permitidas por el firewall y el router. **No publicaremos PostgreSQL en Internet.**

Como hemos cambiado el puerto y las interfaces, reiniciamos:

~~~bash
systemctl restart postgresql
pg_lsclusters
ss -tulnp | grep 5433
~~~

### Usuario administrador de PostgreSQL

Al instalar PostgreSQL, normalmente se crea el usuario Linux `postgres` y el rol administrador de PostgreSQL `postgres`. Son cuentas distintas aunque tengan el mismo nombre.

Desde root pasamos al usuario Linux:

~~~bash
su postgres
~~~

Después entramos en PostgreSQL:

~~~bash
psql
~~~

Para establecer la contraseña del rol `postgres`:

~~~sql
\password postgres
~~~

También puede emplearse:

~~~sql
ALTER USER postgres WITH PASSWORD 'CONTRASEÑA_SEGURA';
~~~

Creamos una base de datos y consultamos las cuentas y bases existentes:

~~~sql
CREATE DATABASE practica_si;
\du
\l
~~~

Salimos de PostgreSQL y después de la cuenta Linux:

~~~sql
\q
~~~

~~~bash
exit
~~~

### Probar la conexión mediante el nuevo puerto

~~~bash
psql -h 127.0.0.1 -p 5433 -U postgres -d practica_si
~~~

Para acceder directamente desde otro equipo de una red autorizada, se sustituye `127.0.0.1` por la IP del servidor.

Recordad sustituir **5433** por el puerto asignado. El rol `postgres` es administrador y solo lo usaremos para las pruebas autorizadas; las aplicaciones reales deberían utilizar roles con permisos limitados.

## 6. pgAdmin 4: administración web de PostgreSQL

pgAdmin 4 permite administrar PostgreSQL desde un navegador. En esta instalación Debian utilizaremos **pgAdmin Web mediante Apache**, por lo que el servicio de systemd que controlaremos será `apache2`.

### Instalación

~~~bash
apt update
apt install -y curl gnupg lsb-release
install -d -m 0755 /etc/apt/keyrings
~~~

Añadimos la clave del repositorio oficial:

~~~bash
curl -fsS https://www.pgadmin.org/static/packages_pgadmin_org.pub | gpg --dearmor -o /etc/apt/keyrings/packages-pgadmin-org.gpg
~~~

Añadimos el repositorio de Debian 13 (Trixie):

~~~bash
echo "deb [signed-by=/etc/apt/keyrings/packages-pgadmin-org.gpg] https://ftp.postgresql.org/pub/pgadmin/pgadmin4/apt/trixie pgadmin4 main" > /etc/apt/sources.list.d/pgadmin4.list
~~~

Instalamos y realizamos la configuración inicial:

~~~bash
apt update
apt install -y pgadmin4-web
PGADMIN_PLATFORM_TYPE=debian /usr/pgadmin4/bin/setup-web.sh
~~~

La cuenta de acceso a pgAdmin es distinta del rol de PostgreSQL.

### Administrar Apache

~~~bash
systemctl status apache2
systemctl start apache2
systemctl stop apache2
systemctl restart apache2
systemctl enable apache2
journalctl -u apache2 -n 20 --no-pager
~~~

### Cambiar el puerto web de pgAdmin

Cada alumno debe utilizar el **puerto de pgAdmin de su rango de la UD2.7**. En este ejemplo explicativo utilizamos **8080**.

Primero comprobamos que el puerto esté disponible:

~~~bash
ss -tulnp | grep 8080
~~~

Apache define sus puertos de escucha en:

~~~bash
nano /etc/apache2/ports.conf
~~~

Si el servidor usa `Listen 80` y no necesita mantener ese puerto para otros sitios, cambiamos la línea por:

~~~apache
Listen 8080
~~~

Consultamos los sitios activos:

~~~bash
apache2ctl -S
~~~

Si pgAdmin utiliza el sitio predeterminado de Apache, editamos:

~~~bash
nano /etc/apache2/sites-available/000-default.conf
~~~

Cambiamos:

~~~apache
<VirtualHost *:80>
~~~

Por:

~~~apache
<VirtualHost *:8080>
~~~

Si Apache publica otras aplicaciones, debemos adaptar el VirtualHost correspondiente sin alterar esos sitios.

Comprobamos la configuración y reiniciamos:

~~~bash
apache2ctl configtest
systemctl restart apache2
ss -tulnp | grep 8080
~~~

**Sustituimos 8080 por el puerto de pgAdmin asignado al alumno.**

### Acceder desde el navegador

Desde la red que tenga acceso directo a nuestro Debian:

~~~text
http://IP_DEL_DEBIAN:8080/pgadmin4
~~~

Desde la red del instituto, si el router tiene configurada la redirección:

~~~text
http://192.168.29.133:8080/pgadmin4
~~~

Las direcciones anteriores son ejemplos: hay que utilizar el puerto asignado. En redes que manejan contraseñas, para un uso permanente debemos configurar HTTPS.

### Registrar PostgreSQL desde pgAdmin

Una vez iniciada la sesión en pgAdmin, registramos el servidor PostgreSQL que acabamos de configurar:

| Parámetro | Valor |
| --- | --- |
| Host | `127.0.0.1` |
| Puerto | Puerto PostgreSQL asignado (por ejemplo, `5433`) |
| Usuario | `postgres` |
| Contraseña | Contraseña configurada en PostgreSQL |
| Base de datos | `practica_si` |

Como pgAdmin y PostgreSQL están instalados en el mismo Debian, podemos conectar pgAdmin a PostgreSQL mediante `127.0.0.1`. El **puerto de pgAdmin** y el **puerto de PostgreSQL** son independientes y ambos deben respetar los valores de la tabla de la UD2.7.
