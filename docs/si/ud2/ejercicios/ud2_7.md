## 2. Instalar y configurar Git

Desde tu Debian, instala Git y las herramientas de Python. Estos comandos de instalación requieren permisos de administrador.

~~~bash
apt update
apt install -y git python3 python3-venv python3-pip
git --version
~~~

Configura la identidad con la que harás los commits:

~~~bash
git config --global user.name "Nombre Apellidos"
git config --global user.email "tu-correo@ejemplo.com"
git config --global --list
~~~

Para que Git recuerde tus credenciales HTTPS entre operaciones:

~~~bash
git config --global credential.helper store
~~~

Al hacer el primer `git clone`, `git pull` o `git push`, introduce tu usuario y el **token de acceso** del servidor Git cuando te pida la contraseña. Git guardará la credencial en `~/.git-credentials`. Comprueba sus permisos:

~~~bash
chmod 600 ~/.git-credentials
~~~

Este método guarda el token **sin cifrar**. Úsalo solo en tu Debian individual y no subas nunca ese archivo al repositorio. La configuración se guarda para el usuario Linux que ejecuta los comandos.

Clona el repositorio de trabajo en `/workspace` (la carpeta debe estar vacía):

~~~bash
mkdir -p /workspace
cd /workspace
git clone URL_DEL_REPOSITORIO .
~~~

Si ya tienes el repositorio clonado, entra en `/workspace` y utiliza `git pull` en lugar de clonarlo de nuevo.

## 4. Crear un entorno virtual de Python

Prepara la carpeta de la actividad:

~~~bash
mkdir -p /workspace/ud2/servicios
cd /workspace/ud2/servicios
python3 -m venv .venv
source .venv/bin/activate
pip install flask
pip freeze > requirements.txt
~~~

El entorno virtual contiene las bibliotecas de este proyecto y no se debe subir a Git.

Para salir del entorno:

~~~bash
deactivate
~~~

Para volver a activarlo:

~~~bash
cd /workspace/ud2/servicios
source .venv/bin/activate
~~~

## 5. Actividad: ejecutar Flask como servicio

Un servicio de sistema se define mediante un archivo `.service` y se administra con `systemctl`. El objetivo es que tu aplicación continúe funcionando sin mantener una terminal abierta y se inicie al arrancar Debian.

### 5.1. Crear la aplicación

Crea `/workspace/ud2/servicios/app.py`:

~~~python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def inicio():
    return "Servicio de Sistemas Informáticos"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=11000, debug=False)
~~~

**Sustituye el puerto 11000 por el primero de tu rango asignado.** Modifica el mensaje para incluir el nombre de tu máquina y añade una segunda ruta `/estado` que devuelva `Servicio activo`.

Prueba la aplicación:

~~~bash
cd /workspace/ud2/servicios
source .venv/bin/activate
python app.py
~~~

Comprueba que responde y deténla con **Ctrl+C** antes de configurar el servicio.

### 5.2. Crear la unidad de systemd

Comprueba que Debian utiliza systemd:

~~~bash
ps -p 1 -o comm=
whoami
~~~

Crea `/workspace/ud2/servicios/ud2-servicio.service`:

~~~ini
[Unit]
Description=Aplicacion Flask de Sistemas Informaticos
After=network.target

[Service]
Type=simple
User=TU_USUARIO
WorkingDirectory=/workspace/ud2/servicios
ExecStart=/workspace/ud2/servicios/.venv/bin/python /workspace/ud2/servicios/app.py
Restart=on-failure

[Install]
WantedBy=multi-user.target
~~~

Sustituye `TU_USUARIO` por el usuario Linux que ejecutará la aplicación, obtenido con `whoami`. Ese usuario debe tener acceso a `/workspace/ud2/servicios`. No hace falta activar el entorno virtual en el archivo: `ExecStart` utiliza directamente su intérprete de Python.

Instala y arranca el servicio con permisos de administrador:

~~~bash
cp /workspace/ud2/servicios/ud2-servicio.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now ud2-servicio.service
systemctl status ud2-servicio.service
~~~

### 5.3. Comprobar su funcionamiento

Utiliza los siguientes comandos:

~~~bash
systemctl stop ud2-servicio.service
systemctl start ud2-servicio.service
systemctl restart ud2-servicio.service
systemctl status ud2-servicio.service
journalctl -u ud2-servicio.service -n 20 --no-pager
~~~

Comprueba desde un navegador de la red del instituto:

~~~text
http://192.168.29.133:TU_PUERTO
http://192.168.29.133:TU_PUERTO/estado
~~~

Sustituye `TU_PUERTO` por el puerto de tu aplicación. Comprueba también que el servicio vuelve a iniciarse al reiniciar tu Debian.
