# UD2.4 · Servicios en Debian: systemd y Flask

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Duración orientativa:** 90 minutos  
**Modalidad:** Individual · Debian GNU/Linux  
**Herramientas:** `python3`, Flask, `systemctl`, `journalctl`, `curl` y `ss`

En esta actividad crearás una **aplicación web muy sencilla con Python**, la ejecutarás como proceso y después aprenderás a administrarla como un servicio de Linux.

!!! danger "Entorno adecuado"
    Para instalar un servicio necesitarás **tu Debian de laboratorio, con `systemd` y permisos autorizados de administrador**. No utilices un servidor compartido ni instales servicios en la máquina de otros alumnos. En algunos contenedores `systemctl` no funciona porque `systemd` no es su proceso de inicio: en ese caso realiza la parte de Flask y consulta al profesor para probar el servicio en otra máquina.

## 1. Procesos y servicios: ¿qué cambia?

- Un **proceso** es un programa en ejecución, identificado por un PID.
- Un **servicio** es una función proporcionada al sistema o a otros programas, normalmente ejecutada y gestionada en segundo plano.
- En Debian, **`systemd`** puede iniciar, detener, reiniciar y supervisar muchos servicios mediante `systemctl`.

Consulta algunos servicios existentes (solo lectura):

~~~bash
systemctl list-units --type=service --state=running
systemctl status ssh --no-pager
~~~

!!! info "Si no existe `ssh`"
    No todos los Debian tienen instalado el servicio SSH. No necesitas instalarlo para continuar.

## 2. Crear una web mínima con Flask

Crea el directorio `/workspace/ud2/flask/` e instala Flask dentro de un entorno virtual:

~~~bash
mkdir -p /workspace/ud2/flask
cd /workspace/ud2/flask

python3 -m venv .venv
.venv/bin/pip install flask
~~~

Si Debian no dispone del módulo `venv`, el profesor puede autorizar la instalación de `python3-venv` en la máquina de laboratorio.

Crea el archivo `app.py`:

~~~python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def inicio():
    return "Hola desde Flask"

@app.route("/estado")
def estado():
    return "Servicio funcionando"

if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5050)
~~~

Prueba la aplicación:

~~~bash
cd /workspace/ud2/flask
.venv/bin/python app.py
~~~

En otra terminal:

~~~bash
curl http://127.0.0.1:5050/
curl http://127.0.0.1:5050/estado
ss -ltn
~~~

Comprueba qué PID tiene el proceso Python. Después detén Flask con **Ctrl+C**.

!!! warning "Solo desarrollo"
    El servidor incorporado de Flask es válido para esta práctica local, **no para publicar una aplicación en producción**. Utilizamos `127.0.0.1` para que la web solo sea accesible desde la propia máquina. La conexión desde otros equipos se estudiará en la UD3.

## 3. ¿Está disponible systemd?

Comprueba qué programa es el proceso 1:

~~~bash
ps -p 1 -o comm=
~~~

Para continuar, la salida debe ser `systemd` y el entorno debe permitir `sudo systemctl`. Si no se cumple, no intentes cambiar el inicio del contenedor: detente aquí y documenta lo aprendido.

## 4. Crear nuestro propio servicio

Primero averigua el usuario actual:

~~~bash
whoami
~~~

Crea el fichero `/workspace/ud2/flask/ud2-flask.service`:

~~~ini
[Unit]
Description=Servidor Flask de practica UD2
After=network.target

[Service]
Type=simple
User=TU_USUARIO
WorkingDirectory=/workspace/ud2/flask
ExecStart=/workspace/ud2/flask/.venv/bin/python /workspace/ud2/flask/app.py
Restart=on-failure

[Install]
WantedBy=multi-user.target
~~~

**Sustituye `TU_USUARIO` por el usuario real que muestra `whoami`**. Ese usuario debe poder leer y ejecutar los archivos del proyecto.

Un servicio de sistema se administra con un fichero de unidad instalado en `/etc/systemd/system/`. En **tu máquina de laboratorio**:

~~~bash
sudo cp /workspace/ud2/flask/ud2-flask.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start ud2-flask
sudo systemctl status ud2-flask --no-pager
~~~

Comprueba que Flask responde:

~~~bash
curl http://127.0.0.1:5050/estado
~~~

!!! tip "Diferencia importante"
    Ahora Flask sigue ejecutándose **aunque cierres la terminal donde escribiste `systemctl start`**: lo gestiona `systemd`. No has utilizado `&` para dejar el programa en segundo plano.

## 5. Detener, reiniciar y revisar registros

Prueba estos comandos **solo con tu servicio `ud2-flask`**:

~~~bash
sudo systemctl restart ud2-flask
sudo systemctl status ud2-flask --no-pager
sudo journalctl -u ud2-flask -n 20 --no-pager
sudo systemctl stop ud2-flask
sudo systemctl status ud2-flask --no-pager
~~~

Cuando el servicio está detenido, comprueba qué ocurre con:

~~~bash
curl http://127.0.0.1:5050/estado
~~~

También puedes probar el arranque automático con:

~~~bash
sudo systemctl enable ud2-flask
systemctl is-enabled ud2-flask
sudo systemctl disable ud2-flask
~~~

**No reinicies el equipo** para hacer esta prueba. Basta comprobar la configuración de arranque.
