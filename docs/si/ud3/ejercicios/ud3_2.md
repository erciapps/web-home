# UD3.2 · Configuración de un router OpenWrt, DHCP y acceso a Internet

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Modalidad:** Individual · GNS3  
**Herramientas:** GNS3, OpenWrt, LuCI, Webterm, VPCS, switch, NAT, `ping`, `show arp` e `ip neigh`  
**Resultado de aprendizaje:** RA5 · Criterios: a), b), d), e) y g)

## Objetivo

Ampliar la red local de la UD3.1 añadiendo un **router OpenWrt**, configurar el servicio **DHCP**, utilizar **Webterm** para administrarlo mediante LuCI y comparar las tablas ARP de los ordenadores y del router. Comprobar también la conexión entre la LAN e Internet.

## 1. Crear el proyecto

Crea un proyecto en GNS3 denominado `UD3_2_ROUTER_damXX`, sustituyendo `damXX` por tu usuario. Puedes partir de la topología de la UD3.1.

Tu proyecto debe contener:

- **Un router OpenWrt con LuCI**.
- **Un switch Ethernet**.
- **Tres ordenadores VPCS**.
- **Un equipo Webterm**, con navegador y terminal Linux.
- **Un nodo NAT** de GNS3.

Realiza las conexiones de esta forma:

~~~text
             NAT (GNS3)
                 |
             eth1 (WAN)
               OpenWrt
             eth0 (LAN)
                 |
               Switch
          /    /   \     \
        PC1   PC2   PC3  Webterm
~~~

!!! warning "Conexiones del router"
    Conecta el **puerto LAN `eth0` de OpenWrt al switch**. El puerto **WAN `eth1` va al nodo NAT**. No intercambies los puertos.

Mantén los nombres de los dispositivos identificados con tu usuario.

## 2. Configurar la red de Webterm

La conexión de Webterm se configura **desde las propiedades del propio nodo en GNS3**, no editando un archivo de configuración manualmente.

1. Detén Webterm si está encendido.
2. Abre la **configuración del nodo Webterm**.
3. En el apartado **Network**, selecciona la interfaz `eth0`.
4. En **IPv4 configuration → Addressing mode**, selecciona **DHCP**.
5. Pulsa **Apply network configuration** y guarda los cambios con **Apply**.
6. Conecta `eth0` de Webterm al switch y arranca el equipo.

Desde la terminal de Webterm comprueba la dirección obtenida:

~~~bash
ip addr
ip route
~~~

Con la configuración inicial habitual de OpenWrt, Webterm recibirá una IP de la red `192.168.1.0/24`. Abre su navegador y accede a:

`http://192.168.1.1`

Desde ahí administrarás OpenWrt mediante **LuCI**.

## 3. Configurar la LAN y el servidor DHCP

Cada alumno utilizará la red **`10.XX.1.0/24`**, donde `XX` corresponde al número de su usuario.

Por ejemplo, el usuario `dam70` trabajará con `10.70.1.0/24`.

En LuCI, entra en **Network → Interfaces → LAN** y configura:

| Parámetro | Valor |
| --- | --- |
| IP del router en la LAN | `10.XX.1.1` |
| Máscara | `255.255.255.0` (`/24`) |
| Primera IP del rango DHCP | `10.XX.1.100` |
| Última IP del rango DHCP | `10.XX.1.149` |

En la configuración DHCP de LuCI puedes establecer **Start = 100** y **Limit = 50** para ese rango. Guarda y aplica los cambios.

!!! info "Cambio de red"
    Al modificar la IP LAN de OpenWrt, el navegador dejará de encontrar el router en `192.168.1.1`. Renueva la dirección DHCP de Webterm (o reinicia ese nodo), comprueba la nueva IP y entra desde Firefox en `http://10.XX.1.1`.

## 4. Configurar PC1, PC2 y PC3 mediante DHCP

Los ordenadores ya no utilizarán las direcciones IP fijas de la UD3.1: deben obtener su configuración de forma **automática** desde OpenWrt.

Desde la consola de cada VPCS:

~~~text
ip dhcp
show ip
~~~

Comprueba que cada equipo recibe una dirección IP de tu rango, una máscara `/24` y como **puerta de enlace** la IP LAN de OpenWrt.

Si lo prefieres, puedes dejar configurado el comando `dhcp` desde las propiedades del propio nodo VPCS para que solicite la dirección al arrancar. Comprueba igualmente el resultado desde la consola.

Realiza `ping` desde PC1 hacia PC2, PC3 y la IP LAN del router.

## 5. Comprobar la WAN y el acceso a Internet

**La WAN de OpenWrt ya dispone de una dirección IP:** no es necesario modificarla.

En LuCI, localiza la interfaz **WAN** y observa su IP, puerta de enlace y estado. Comprueba que el nodo NAT está conectado correctamente.

Desde Webterm realiza:

~~~bash
ping -c 4 10.XX.1.1
ping -c 4 1.1.1.1
~~~

Sustituye `XX` por tu identificador. Desde los VPCS, comprueba también si puedes alcanzar una dirección externa:

~~~text
ping 1.1.1.1
~~~

Si la LAN funciona pero no hay conexión exterior, revisa las conexiones, el estado de la WAN y la salida NAT de OpenWrt, sin cambiar la dirección WAN asignada.

## 6. Comparar las tablas ARP

### 6.1. En PC1 (VPCS)

Ejecuta:

~~~text
show arp
ping 10.XX.1.1
show arp
~~~

Después realiza `ping` a la dirección actual de PC2 y vuelve a ejecutar `show arp`.

Observa qué direcciones IP y MAC aparecen.

### 6.2. En Webterm (Linux)

Desde la terminal:

~~~bash
ip neigh show
~~~

Haz `ping` a la IP real de PC1 (consulta primero su `show ip`), por ejemplo:

~~~bash
ping -c 4 10.XX.1.100
ip neigh show
~~~

La dirección `.100` es solamente un ejemplo: DHCP puede haber asignado otra distinta.

### 6.3. En OpenWrt

Desde Firefox en Webterm, abre LuCI en `http://10.XX.1.1` y busca **Status → Routing → IPv4 Neighbours**.

También puedes consultar los vecinos IPv4 desde la terminal de OpenWrt:

~~~bash
ip neigh show
ip neigh show dev br-lan
~~~

!!! tip "Recuerda"
    La **tabla ARP** relaciona direcciones IP y MAC de vecinos conocidos. La **tabla MAC del switch** relaciona las MAC aprendidas con sus puertos. Si PC1 hace `ping` a PC2 dentro de la misma LAN, no necesita que los paquetes pasen por OpenWrt.

En GNS3 abre **Edit project → Readme**.

2. ¿Qué diferencia existe entre la dirección **LAN** y la dirección **WAN** del router?
3. ¿Qué configuración reciben los equipos automáticamente mediante **DHCP**?
4. ¿Qué función tiene la **puerta de enlace** al acceder a Internet?
5. ¿Qué diferencias observas entre las tablas ARP de **VPCS, Webterm y OpenWrt**?
6. Si PC1 se comunica con PC2, ¿deben pasar los paquetes por el router? Razona la respuesta.

El README utiliza **Markdown**. Comprueba que los cambios están guardados antes de exportar el proyecto.

## 8. Entrega

Comprueba que:

- Los tres VPCS y Webterm están conectados al switch.
- OpenWrt tiene su **LAN en `10.XX.1.1/24`** y conserva la IP de su WAN.
- El servidor DHCP asigna direcciones del rango indicado.
- Webterm puede acceder a la administración de OpenWrt mediante LuCI.
- Los equipos pueden comunicarse entre sí y salir a Internet.
- Has consultado las tablas ARP de los tres entornos.
- El **README del proyecto** incluye todas las respuestas.

Detén los dispositivos y utiliza **Export portable project** para entregar:

`UD3_2_ROUTER_damXX.gns3project`

No se requiere PDF ni capturas. El proyecto debe poder importarse y comprobarse.
