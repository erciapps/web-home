# UD3.3 · Administración de un switch MikroTik RouterOS

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Modalidad:** Individual · GNS3  
**Herramientas:** MikroTik CHR, WinBox, Webterm y VPCS  
**Resultado de aprendizaje:** RA5 · Criterios: b), d) y g)

## Objetivo

Sustituir el switch básico de GNS3 por un **switch administrable MikroTik**, comprobar cómo aprende las direcciones MAC y administrar sus puertos desde **WinBox**.

## 1. Preparar el proyecto

Crea un proyecto llamado `UD3_3_SWITCH_damXX` a partir de la UD3.2. Conserva el MikroTik que actúa como router, el nodo NAT, WinBox y los equipos. Añade un segundo MikroTik CHR con al menos seis interfaces, que actuará como switch. Identifica ambos dispositivos con nombres distintos.

La topología final será:

~~~text
             NAT
              |
        MikroTik Router
              |
         ether1 (MikroTik Switch)
         /    |    |     |     \
       e2    e3   e4     e5    e6
       |     |    |      |     |
      PC1   PC2  PC3  Webterm WinBox
~~~

Usa **la misma red `10.XX.1.0/24` y el mismo DHCP de MikroTik Router**. No cambies su WAN.

## 2. Configurar el switch desde WinBox

Un **bridge** agrupa interfaces para que intercambien tramas Ethernet como un switch de capa 2. Aprende las MAC de origen y reenvía las tramas por el puerto correspondiente. No es una lista de interfaces para aplicar políticas de firewall. En esta práctica el segundo MikroTik actúa como switch; el primero conserva el enrutamiento, DHCP y NAT.

Mantén **WinBox y Webterm en DHCP** desde las propiedades Network de GNS3, tal como se explicó en la [UD3.2](ud3_2.md#2-configurar-winbox-y-webterm-en-gns3).

1. Mientras preparas el segundo MikroTik, mantenlo conectado al switch básico de GNS3 para acceder a él desde el nodo WinBox.
2. En **Neighbors**, identifica el segundo MikroTik por su MAC y conéctate a él. Si no aparece, consulta las concesiones en **IP → DHCP Server → Leases** del router, o ejecuta `/ip address print` en la consola del segundo MikroTik y conecta por su IP si pertenece a la LAN.
3. En **System → Identity**, asigna un nombre diferente al del router.
4. En **Quick Set**, selecciona **Mode → Bridge**, **Address Acquisition → Automatic** y aplica los cambios. Si se pierde la conexión, consulta la nueva IP desde la consola o las concesiones del router. En **Bridge → Bridge**, comprueba el bridge creado y reutilízalo; si no existe, crea `bridge-lan`. Mantén VLAN Filtering desactivado.
5. En **Bridge → Ports**, comprueba que están incorporados (añade solo los que falten) `ether1`, `ether2`, `ether3`, `ether4`, `ether5` y `ether6` al mismo bridge.
6. Comprueba en **IP → DHCP Client** que el cliente DHCP para la IP de administración está asociado al bridge y tiene estado bound. No mantengas un cliente DHCP adicional sobre un puerto miembro. Consulta la dirección asignada en **IP → DHCP Server → Leases** del primer MikroTik.
7. El segundo MikroTik no debe tener servidor DHCP ni reglas NAT: su función es exclusivamente la de switch.

!!! tip "Acceso mediante MAC"
    Si se interrumpe la conexión, intenta Neighbors desde la misma LAN o conecta mediante la IP de administración obtenida por DHCP. Comprueba que WinBox tiene una IPv4 del mismo segmento.

Con el bridge preparado, conecta todos los equipos directamente al segundo MikroTik según la topología y elimina el switch básico. No mantengas enlaces redundantes. Comprueba que WinBox puede acceder a ambos MikroTik por sus respectivas IP y que Webterm sigue recibiendo DHCP.

## 3. Comprobar conexiones y tabla MAC

1. Desde cada VPCS, ejecuta `ip dhcp` y `show ip` para comprobar la dirección recibida.
2. Realiza `ping` entre los ordenadores y hacia MikroTik Router (`10.XX.1.1`).
3. En WinBox del segundo MikroTik, abre **Bridge → Hosts** y observa las **direcciones MAC aprendidas y sus puertos**.
4. Desde **Interfaces**, desactiva el puerto `ether3` (PC2) y comprueba qué ocurre con la comunicación. **Vuelve a activarlo** y repite la prueba.

!!! tip "ARP y tabla MAC"
    La **tabla ARP** de un ordenador o de MikroTik Router relaciona IP y MAC. La **tabla MAC** de MikroTik relaciona MAC y puerto del switch. Puedes compararlas con `show arp` en VPCS, **IP → ARP** en el router y **Bridge → Hosts** en el switch. Desde terminal, los comandos equivalentes son `/ip arp print` y `/interface bridge host print`.
