# UD3.3 · Administración de un switch MikroTik RouterOS

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Modalidad:** Individual · GNS3  
**Herramientas:** MikroTik CHR, WinBox, Webterm y VPCS  
**Resultado de aprendizaje:** RA5 · Criterios: b), d) y g)

## Objetivo

Sustituir el switch básico de GNS3 por un **switch administrable MikroTik**, comprobar cómo aprende las direcciones MAC y administrar sus puertos desde **WinBox**.

## 1. Preparar el proyecto

Crea un proyecto llamado `UD3_3_SWITCH_damXX` a partir de la UD3.2. Conserva el MikroTik que actúa como router, el nodo NAT, WinBox y los equipos. Añade un segundo MikroTik CHR con al menos seis interfaces, que actuará como switch. Identifica ambos dispositivos con nombres distintos.

La topología final será:

~~~text
             NAT
              |
        MikroTik Router
              |
         ether1 (MikroTik Switch)
         /    |    |     |     \
       e2    e3   e4     e5    e6
       |     |    |      |     |
      PC1   PC2  PC3  Webterm WinBox
~~~

Usa **la misma red `10.XX.1.0/24` y el mismo DHCP de MikroTik Router**. No cambies su WAN.

## 2. Configurar el switch desde WinBox

1. Mientras preparas el segundo MikroTik, mantenlo conectado al switch básico de GNS3 para acceder a él desde el nodo WinBox.
2. En **Neighbors**, identifica el segundo MikroTik por su MAC y conéctate a él.
3. En **System → Identity**, asigna un nombre diferente al del router.
4. En **Bridge**, crea un bridge llamado `bridge-lan`.
5. En **Bridge → Ports**, incorpora `ether1`, `ether2`, `ether3`, `ether4`, `ether5` y `ether6` al mismo bridge.
6. Comprueba en **IP → DHCP Client** que, si quieres una IP de administración, el cliente DHCP está asociado al bridge. Consulta la dirección asignada en **IP → DHCP Server → Leases** del primer MikroTik.
7. El segundo MikroTik no debe tener servidor DHCP ni reglas NAT: su función es exclusivamente la de switch.

!!! tip "Acceso mediante MAC"
    Si se interrumpe la conexión, vuelve a conectarte mediante Neighbors en WinBox desde la misma LAN.

Con el bridge preparado, conecta todos los equipos directamente al segundo MikroTik según la topología y elimina el switch básico.

## 3. Comprobar conexiones y tabla MAC

1. Desde cada VPCS, ejecuta `ip dhcp` y `show ip` para comprobar la dirección recibida.
2. Realiza `ping` entre los ordenadores y hacia MikroTik Router (`10.XX.1.1`).
3. En WinBox, abre **Bridge → Hosts** y observa las **direcciones MAC aprendidas y sus puertos**.
4. Desde **Interfaces**, desactiva el puerto `ether3` (PC2) y comprueba qué ocurre con la comunicación. **Vuelve a activarlo** y repite la prueba.

!!! tip "ARP y tabla MAC"
    La **tabla ARP** de un ordenador o de MikroTik Router relaciona IP y MAC. La **tabla MAC** de MikroTik relaciona MAC y puerto del switch. Puedes compararlas con `show arp` en VPCS y **Bridge → Hosts** en WinBox.

## 4. Preguntas en el README

Abre **Edit project → Readme** e incluye tu **nombre, primer apellido, usuario y red utilizada**. Responde brevemente:

1. ¿Para qué sirve el bridge de MikroTik?
2. ¿Qué información muestra **Bridge → Hosts** y cómo aprende el switch esa información?
3. ¿Qué sucede al desactivar `ether3`?
4. ¿Qué diferencia hay entre una tabla ARP y la tabla MAC del switch?

## 5. Entrega

Comprueba que el bridge funciona, todos los equipos tienen conexión, has observado la tabla MAC, has reactivado `ether3` y has completado el README.

Guarda la configuración de los VPCS con `save`, detén los dispositivos y utiliza **Export portable project** para entregar:

`UD3_3_SWITCH_damXX.gns3project`

**No es necesario entregar PDF ni capturas.**
