# UD3.1 · Creación de una red local con GNS3

**Módulo:** Sistemas Informáticos · 1.º DAM  
**Modalidad:** Individual · GNS3  
**Herramientas:** GNS3, VPCS, switch Ethernet, `ip`, `show ip`, `ping`, `show arp` y `save`  
**Resultado de aprendizaje:** RA5 · Criterios: a), b), d) y g)

## Objetivo

Crear una **red local cableada**, configurar direcciones IPv4 y comprobar cómo se comunican los equipos a través de un **switch**, utilizando los comandos básicos de VPCS.

## 1. Crear el proyecto

Entra en **GNS3** con tu usuario y crea un proyecto denominado `UD3_1_LAN_damXX`, sustituyendo `damXX` por tu identificador.

Añade estos dispositivos:

- **Tres ordenadores VPCS**.
- **Un switch Ethernet**.

Conéctalos con esta topología:

~~~text
           Switch
          /  |  \
        PC1 PC2  PC3
~~~

Renombra también los dispositivos incluyendo tu usuario. Ejemplo para `dam70`: `PC1_dam70`, `PC2_dam70`, `PC3_dam70` y `SW_dam70`.

## 2. Configurar las direcciones IP

Cada alumno utilizará la red **`10.XX.1.0/24`**, donde `XX` es el número de su usuario.

Por ejemplo, `dam70` utilizará `10.70.1.0/24`.

Configura manualmente las siguientes direcciones:

| Equipo | Dirección IP | Máscara |
| --- | --- | --- |
| PC1 | `10.XX.1.10` | `255.255.255.0` (`/24`) |
| PC2 | `10.XX.1.11` | `255.255.255.0` (`/24`) |
| PC3 | `10.XX.1.12` | `255.255.255.0` (`/24`) |

Arranca los equipos y configura su IP desde la consola de VPCS. Utiliza `help` si necesitas consultar la sintaxis y `show ip` para revisar los resultados.

!!! info "Sin router"
    No necesitas configurar **puerta de enlace** ni conexión a Internet: los tres equipos pertenecen a la misma red local.

## 3. ¿Qué ocurre cuando PC1 hace ping?

Vamos a entender cómo se comunica PC1 con PC2. En este ejemplo usamos el usuario `dam70` y direcciones MAC abreviadas para facilitar la explicación.

### Paso 1. PC1 busca la dirección MAC de PC2

PC1 conoce la IP `10.70.1.11`, pero todavía no sabe su dirección MAC.

Envía una petición **ARP**:

*«¿Quién tiene la IP 10.70.1.11?»*

Como es una petición **broadcast**, el switch la envía a todos los demás puertos de la misma LAN, excepto al puerto por el que ha llegado.

### Paso 2. PC2 responde

PC2 reconoce su dirección IP y responde:

*«Soy yo y mi dirección MAC es BB:BB».*

Los demás ordenadores reciben la petición ARP, pero normalmente no responden.

PC1 guarda la correspondencia **IP → MAC** en su tabla ARP.

### Paso 3. El switch aprende dónde está PC2

El switch aprende las **direcciones MAC de origen** de las tramas que recibe y las relaciona con el puerto correspondiente.

Tras intercambiar tráfico entre los tres equipos, su tabla MAC podría contener:

| Puerto | MAC aprendida |
| --- | --- |
| e0 | AA:AA (PC1) |
| e1 | BB:BB (PC2) |
| e2 | CC:CC (PC3) |

Esta tabla se denomina **tabla MAC o tabla CAM**. Ten en cuenta que el switch no aprende la MAC de PC3 hasta que PC3 envía alguna trama.

### Paso 4. PC1 envía el ping a PC2

Ahora PC1 conoce la MAC de PC2 y envía una trama dirigida a `BB:BB`.

Como el switch ya sabe en qué puerto está esa MAC, **envía la trama solamente al puerto de PC2**, en lugar de enviarla a todos los equipos.

## 4. Comprobar la comunicación

Desde **PC1**, realiza estas pruebas **en orden**:

1. Ejecuta `show arp` antes de comunicarte con los demás equipos y observa el resultado.
2. Ejecuta `ping` a la IP de **PC2**.
3. Vuelve a ejecutar `show arp` y comprueba si aparece la MAC de PC2.
4. Realiza `ping` a la IP de **PC3**.
5. Comprueba también que **PC2 y PC3** se comunican entre sí.
6. Revisa las direcciones con `show ip` y guarda la configuración de cada PC con `save`.

!!! tip "¿Qué debes observar?"
    La **tabla ARP de un PC** relaciona IP con MAC. La **tabla MAC del switch** relaciona MAC con puertos. No son la misma tabla.

## 5. Preguntas sobre ARP y el switch

Abre **Edit project → Readme** en GNS3. En este apartado escribe tu **nombre y primer apellido, usuario, red utilizada y las respuestas** a estas preguntas. Utiliza formato Markdown y deja que el README se guarde antes de exportar el proyecto:

1. Si el switch no utiliza las IP para reenviar tramas, ¿qué direcciones utiliza?
2. Cuando PC1 no conoce la MAC de PC2, ¿cómo consigue averiguarla y quién recibe la petición inicial?
3. Una vez que el switch aprende dónde está PC2, ¿envía las tramas dirigidas a PC2 a todos los equipos o únicamente a su puerto?
4. ¿Qué diferencia existe entre la **tabla ARP** de un PC y la **tabla MAC** del switch?

## 6. Entrega

Antes de entregar, comprueba que:

- Los tres ordenadores están conectados al switch.
- Cada equipo tiene una IP distinta dentro de tu red asignada.
- Los tres ordenadores pueden comunicarse mediante `ping`.
- Has guardado la configuración con `save` en **cada VPCS**.
- El proyecto y los dispositivos incluyen tu usuario.
- El **README del proyecto** contiene tus datos y las respuestas a las cuatro preguntas.

Detén los dispositivos, comprueba que el README está guardado y utiliza **Export portable project** de GNS3. Entrega el archivo:

`UD3_1_LAN_damXX.gns3project`

**No es necesario entregar PDF ni capturas.** El proyecto debe poder importarse y comprobarse sin volver a configurar los equipos.
