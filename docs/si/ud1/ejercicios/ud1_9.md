# UD1.9 · Validador automático de entregas

Hasta ahora hemos **creado, copiado y movido** archivos. Ahora realizaremos un script que lea requisitos de un fichero y compruebe si otra carpeta cumple lo pedido. **No debe crear ni modificar los archivos que valida.**

!!! info "Entorno de trabajo"
    El programa será `/workspace/ud1/ud1_9.sh` y todos los datos estarán dentro de `/workspace/ud1/pruebas/ud1_9`.

## 1. Comandos nuevos: explicación antes del ejercicio

| Comprobación | ¿Cuándo se cumple? |
| --- | --- |
| `[[ -d "$ruta" ]]` | La ruta existe y es un **directorio**. |
| `[[ -f "$ruta" ]]` | La ruta existe y es un **archivo normal**. |
| `[[ -s "$ruta" ]]` | La ruta existe y su tamaño es **mayor que cero**. |

```bash
ruta="./pruebas/ud1_9/entrega/README.md"

if [[ -f "$ruta" ]];then
    echo "El archivo existe"
else
    echo "Falta el archivo"
fi
```

### `grep`: comprobar si hay un texto

`grep` busca contenido en archivos. `-F` trata el texto literalmente y `-q` evita imprimir las coincidencias:

```bash
if grep -Fq "UD1.9" ./pruebas/ud1_9/entrega/README.md;then
    echo "El texto está presente"
else
    echo "El texto no aparece"
fi
```

### `wc`: contar líneas

`wc -l` cuenta **saltos de línea**. Si cada registro acaba en un salto de línea, sirve para contar registros:

```bash
totalLineas=$(wc -l < ./pruebas/ud1_9/requisitos.txt)
```

### `$?`: resultado del último comando

`$?` guarda el código de salida del comando **inmediatamente anterior**. `0` indica éxito; otro código puede indicar error o, según el programa, otro resultado (por ejemplo, `grep` devuelve `1` cuando no encuentra coincidencias).

```bash
cp ./pruebas/ud1_9/original.txt ./pruebas/ud1_9/copia.txt

if [[ $? == 0 ]];then
    echo "Copia realizada"
else
    echo "No se pudo copiar"
fi
```

!!! tip "Importante"
    Comprueba `$?` inmediatamente, antes de ejecutar otro comando. Para `grep`, en este ejercicio es más sencillo utilizar `if grep ...;then`.

## 2. Preparar una entrega de prueba

Crea manualmente:

```text
pruebas/ud1_9/
├── requisitos.txt
└── entrega/
    ├── README.md
    ├── java/
    │   ├── models/
    │   └── views/
    └── resources/
        └── img/
```

En `README.md` escribe una línea que contenga `UD1.9`. Deja inicialmente sin crear `java/controllers` y `java/Main.java` para comprobar que el validador detecta errores.

## 3. Fichero `requisitos.txt`

Cada línea indica qué queremos comprobar. Utilizaremos rutas relativas a `/workspace/ud1`:

```text
DIR;./pruebas/ud1_9/entrega/java/models
DIR;./pruebas/ud1_9/entrega/java/views
DIR;./pruebas/ud1_9/entrega/java/controllers
FILE;./pruebas/ud1_9/entrega/README.md
FILE;./pruebas/ud1_9/entrega/java/Main.java
NOTEMPTY;./pruebas/ud1_9/entrega/README.md
TEXT;./pruebas/ud1_9/entrega/README.md;UD1.9
```

| Instrucción | Campos | Comprobación |
| --- | --- | --- |
| `DIR` | Operación y ruta | `[[ -d "$ruta" ]]` |
| `FILE` | Operación y ruta | `[[ -f "$ruta" ]]` |
| `NOTEMPTY` | Operación y ruta | `[[ -s "$ruta" ]]` |
| `TEXT` | Operación, ruta y texto | `grep -Fq` |

## 4. Leer los requisitos con nuestra forma de programar

El script comenzará así:

```bash
BASE="$(dirname "$0")"
cd "$BASE"

correctos=0
errores=0
totalLineas=$(wc -l < ./pruebas/ud1_9/requisitos.txt)

for ((i=1; i<=$totalLineas; i++));do
    linea=$(sed -n "$i"'p' ./pruebas/ud1_9/requisitos.txt)
    IFS=';' read -ra datos <<< "$linea"

    instruccion="${datos[0]}"
    ruta="${datos[1]}"
    texto="${datos[2]}"

    # Completa las comprobaciones con if [[ ... ]] y elif [[ ... ]]
done
```

En cada vuelta, utiliza `if [[ ... ]]` y `elif [[ ... ]]` para elegir la comprobación. Muestra `[OK]` si se cumple o `[ERROR]` en caso contrario, e incrementa los contadores con `correctos=$((correctos+1))` o `errores=$((errores+1))`.

!!! note "Caso TEXT"
    Primero comprueba con `[[ -f "$ruta" ]]` que el archivo existe. Después usa `grep -Fq "$texto" "$ruta"`. Mantén las condiciones claras, como en los ejercicios anteriores.
